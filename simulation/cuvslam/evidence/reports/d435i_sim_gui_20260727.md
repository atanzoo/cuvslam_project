# D435i Simulation GUI Change Record

Date: 2026-07-27

## Scope

Change class: C1 operator workflow helper.

Acceptance criteria:

- The existing Jetson Connection GUI starts the simulated D435i with one click.
- Success is reported only after both services are active and all required sensor topics exist.
- The GUI can stop the complete simulation process group.
- Repeated Start is idempotent.

Follow-up display requirement:

- Use a white operator area with compact, left-aligned controls.
- Keep the work log black and readable.
- Show an always-visible, draggable vertical log position control.
- Record every button request and important backend transition.

Protected scope:

- No ROS package, world, sensor contract, TF contract, or cuVSLAM configuration changed.
- No dependency was installed.

## Changed Files

- `Jetson Connection.command`
  - Starts the localhost Web GUI instead of the incompatible Tk renderer.
- `tools/jetson_connection_gui.py`
  - Adds Start simulation, Stop, and Refresh status actions.
  - Uses explicitly colored classic Tk widgets because the installed Tcl/Tk
    8.5.9 does not render `ttk` content correctly in the current macOS dark mode.
  - Adds a side work log with Copy log and Clear log controls.
  - Reports endpoint probing, selected SSH target, service transitions, D435i
    topic readiness, elapsed time, cleanup, and errors.
  - Moves network probing and SSH operations off the UI thread.
  - Uses a thread-safe event queue because Tcl/Tk 8.5 cannot reliably accept
    direct `after()` calls from the worker thread.
  - Runs Gazebo and the ROS bridge as transient user systemd services on the Jetson.
  - Uses ROS domain 43 and Ignition partition `cuvslam_d435i_gui`.
  - Verifies the D435i stereo image, camera info, and IMU topics before reporting success.
  - Cleans up both units after a partial or failed start.
- `tools/jetson_connection_web.py`
  - Adds a dependency-free localhost HTTP API and responsive operator UI.
  - Opens as a standalone Chrome app window when Chrome is installed.
  - Uses a white left control pane and a black right log pane.
  - Provides an always-visible draggable log slider, Copy log, and Clear log.
  - Runs Check, Reconnect, Start, Stop, and Refresh asynchronously.
  - Reuses the previously verified Jetson SSH/systemd backend.

Remote transient units:

- `cuvslam-d435i-gazebo.service`
- `cuvslam-d435i-bridge.service`

Required topics:

- `/d435i/infra1/camera_info`
- `/d435i/infra1/image_rect_raw`
- `/d435i/infra2/camera_info`
- `/d435i/infra2/image_rect_raw`
- `/d435i/imu`

## Tests Not Run

- No cuVSLAM estimator launch or pose-output validation. This GUI change starts only
  the confirmed D435i sensor simulation and bridge.
- No long-duration soak test.
- No automated screenshot comparison. Full-screen capture was rejected to avoid
  collecting unrelated on-screen content; native widget mapping and geometry were
  verified instead.

## Residual Risk

- The GUI depends on key-based, non-interactive SSH access to the Jetson.
- The Web GUI server binds only to `127.0.0.1:8765`.
- The standalone window uses Google Chrome when installed and falls back to the
  default browser otherwise.
- A Jetson reboot stops the transient services; press Start simulation again.
- Topic readiness proves the simulated sensor interface is available, not that
  cuVSLAM is consuming it.

## Rollback

Restore the previous two local files, or remove the simulation section and switch
`Jetson Connection.command` back to its former Python invocation. On the Jetson,
stop any active units with:

```bash
systemctl --user stop cuvslam-d435i-bridge.service cuvslam-d435i-gazebo.service
```
